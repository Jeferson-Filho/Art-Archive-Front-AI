# Use Cases — Context Information (Insight Card)

Covers RF-001–RF-010 and their related non-functional requirements.

---

## User Stories

**US-001**
As a **User**,
I want **to read a historical context about the artwork and its artist when I open an artwork's page**,
so that **I can understand its period, artistic movement, and cultural influences without searching another source**.

> Related RFs/RNFs: RF-001, RF-002, RF-004, RF-005, RF-006, RF-008
> Related use cases: UC-01, UC-02, UC-03

---

**US-002**
As a **User**,
I want **to see a comparison to at least one other artist or artwork with a similar period, technique, or culture**,
so that **I can expand my artistic repertoire starting from a piece I'm already interested in**.

> Related RFs/RNFs: RF-001, RF-003, RF-004, RF-005, RF-006, RF-008
> Related use cases: UC-01, UC-02, UC-03

---

**US-003**
As a **returning User**,
I want **the context information of an artwork I've already visited to load almost instantly**,
so that **my browsing isn't slowed down by a wait I've already paid once**.

> Related RFs/RNFs: RF-001, RNF-001
> Related use cases: UC-02

---

**US-004**
As a **User**,
I want **to be told clearly when no context information could be generated for an artwork, instead of seeing a broken or empty section**,
so that **I understand the AI simply had nothing reliable to say, and I can still use the rest of the page**.

> Related RFs/RNFs: RF-005, RF-007, RNF-008
> Related use cases: UC-04

---

**US-005**
As a **User**,
I want **to see the sources the AI used to write the context information, when available**,
so that **I can judge how trustworthy the text is and go read more if I want**.

> Related RFs/RNFs: RF-009, RF-010
> Related use cases: UC-01, UC-05

---

## Detailed Use Cases

### UC-01 — Generate Context Information on First Visit (Both Blocks Missing)

| Field                | Detail                                                                                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Primary Actor**    | User (Visitor)                                                                                                                                                                                                               |
| **Secondary Actors** | Art Archive System, Multimodal LLM, Harvard Art Museums API, PostgreSQL                                                                                                                                                      |
| **Preconditions**    | The User is on an artwork's detail page; neither the historical context block nor the comparative analysis block exists in the database for this artwork                                                                     |
| **Postconditions**   | Both blocks (or their empty-string equivalents) have been resolved; every non-empty block is persisted under the artwork's ID with its prompt version; the disclosure notice and any sources are shown alongside the content |

**Main Flow**

1. The User opens an artwork's detail page.
2. The system checks the database independently for the historical context block and the comparative analysis block.
3. The system finds that neither block exists.
4. The front-end displays a single loading state for the "Context information" section; the rest of the page (title, image, metadata) stays visible and usable.
5. The back-end sends the artwork's image and Harvard metadata (title, artist, technique, culture, period) to the LLM in two separate calls — one per block — each allowed to use open web search.
6. The LLM returns each block's text (or an empty string) together with the pages it consulted.
7. The back-end discards any consulted source that carries no relevant information about the artwork, artist, period, technique, or culture.
8. The back-end persists only the non-empty blocks, tagged with the prompt version used, under the artwork's ID.
9. The back-end returns the available content and remaining sources to the front-end.
10. The front-end renders the "Context information" section only once both blocks are resolved, as paragraphs, with the AI-disclosure notice and any sources.

**Alternative / Exception Flows**

- **5a.** Both AI calls exceed the 60-second shared budget (RNF-002) with no response → proceeds to **UC-04** (timeout variant).
- **6a.** The LLM lacks reliable information for a block → that block is returned as an empty string, not persisted, and retried on the artwork's next visit; if the other block succeeded, only its text is shown.
- **8a.** Persistence fails for a block → the content is still returned to the User; the error is logged, with no visible impact.

**Acceptance Criteria**

```gherkin
Feature: Generation of both Insight Card blocks on first visit

  Scenario: Neither block is persisted yet
    Given the User accesses an artwork's detail page
    And neither the historical context nor the comparative analysis block is stored for this artwork
    When the page finishes loading
    Then the system displays a single loading state for the "Context information" section
    And the back-end triggers two separate AI calls, one per block
    And persists only the blocks that returned non-empty content
    And the "Context information" section is displayed only once both blocks are resolved
    And the AI-disclosure notice is shown alongside the content
```

> Related RFs/RNFs: RF-001, RF-002, RF-003, RF-004, RF-005, RF-006, RF-008, RF-009, RF-010 · RNF-002, RNF-003, RNF-005, RNF-006, RNF-007

### UC-02 — View an Already-Persisted Context Information (Cache)

| Field                | Detail                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| **Primary Actor**    | User (Visitor)                                                                                     |
| **Secondary Actors** | Art Archive System, PostgreSQL                                                                     |
| **Preconditions**    | Both the historical context and comparative analysis blocks are already persisted for this artwork |
| **Postconditions**   | The content is displayed without any AI API call                                                   |

**Main Flow**

1. The User opens an artwork's detail page.
2. The system checks the database and finds both blocks already persisted.
3. The system returns both blocks directly, without invoking the LLM.
4. The front-end displays the "Context information" section immediately, with the disclosure notice and any stored sources.

**Alternative / Exception Flows**

- None — this is the happy path of the persistence mechanism (see **UC-03** for the partial case).

**Acceptance Criteria**

```gherkin
Feature: Display of Insight Card content from the database

  Scenario: Both blocks already stored
    Given both blocks are already stored in the database for an artwork
    When any User accesses that artwork's detail page
    Then the system returns the content from the database
    And no request is made to the AI API
    And each block's response is delivered in at most 500ms for 95% of requests
```

> Related RFs/RNFs: RF-001, RF-005, RF-008 · RNF-001

### UC-03 — Regenerate Only the Missing Block

| Field                | Detail                                                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **Primary Actor**    | User (Visitor)                                                                                                   |
| **Secondary Actors** | Art Archive System, Multimodal LLM, PostgreSQL                                                                   |
| **Preconditions**    | Exactly one of the two blocks (historical context or comparative analysis) is already persisted for this artwork |
| **Postconditions**   | The missing block is generated and, if non-empty, persisted; both blocks are shown together                      |

**Main Flow**

1. The User opens an artwork's detail page.
2. The system checks the database and finds one block persisted and the other missing.
3. The front-end displays a single loading state for the "Context information" section.
4. The back-end triggers a single AI call for only the missing block; the already-persisted block is not regenerated.
5. The back-end persists the newly generated block if non-empty.
6. The front-end renders both blocks together once the missing one is resolved.

**Alternative / Exception Flows**

- **4a.** The regenerated block comes back empty (insufficient information) → it is not persisted and is retried on the next visit; the section shows only the already-persisted block's text.

**Acceptance Criteria**

```gherkin
Feature: Partial regeneration of the Insight Card

  Scenario: Only the historical context block is missing
    Given the comparative analysis block is already stored for an artwork
    And the historical context block is not stored
    When the User accesses the artwork's detail page
    Then the back-end triggers a single AI call to generate only the historical context block
    And no AI call is made to regenerate the comparative analysis block
    And the "Context information" section shows both blocks together only once the missing one is ready
```

> Related RFs/RNFs: RF-001, RF-002, RF-003, RF-004, RF-005

### UC-04 — Handle Total Failure of Context Information Generation

| Field                | Detail                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Primary Actor**    | User (Visitor)                                                                                                      |
| **Secondary Actors** | Art Archive System, Multimodal LLM, Assistive Technology                                                            |
| **Preconditions**    | Neither block is persisted for this artwork, and generation of **both** blocks fails                                |
| **Postconditions**   | No content is persisted; the User is informed via the Insight Card area only; the rest of the page stays functional |

**Main Flow**

1. The User opens an artwork's detail page with no persisted context information.
2. The system triggers generation for both blocks.
3. Both calls fail (error, malformed response, insufficient data, or timeout).
4. The back-end returns an error response to the front-end.
5. The front-end displays a message in the Insight Card area only — the standard fallback message if the failures are not both timeouts, or a timeout-specific message if both are timeouts.
6. The artwork's title, image, and metadata remain visible and functional.

**Alternative / Exception Flows**

- **1a.** Only one of the two blocks fails → this is **not** UC-04; per RF-007 the User simply sees the successful block's text with no error shown (see UC-01/UC-03).
- **5a.** If the User navigates with a screen reader, the message is announced automatically via `aria-live`, without needing to move focus to the component (see UC-06 in [03.3-aria-accessibility.md](03.3-aria-accessibility.md)).

**Acceptance Criteria**

```gherkin
Feature: Total failure of Insight Card generation

  Scenario: Both blocks fail with a non-timeout or mixed error
    Given the User accesses an artwork's detail page with no persisted content
    And generation of both blocks fails, and at least one failure is not a timeout
    When the front-end receives the response
    Then it displays "Was not possible to generate an educational text for this artwork." in the Insight Card area
    And the rest of the page remains functional

  Scenario: Both blocks fail due to timeout
    Given the User accesses an artwork's detail page with no persisted content
    And both AI calls exceed the configured time limit
    When the timeout is reached for both blocks
    Then the front-end displays a timeout-specific message in the Insight Card area
    And the artwork's title, image, and metadata remain visible and functional
```

> Related RFs/RNFs: RF-005, RF-007 · RNF-008
