# Use Cases — Alt Text

Covers RF-011–RF-013.

---

## User Stories

**US-006**
As a **User relying on the image's text alternative (screen reader, slow connection, or the image failing to load)**,
I want **a description of what the artwork's image actually shows**,
so that **I don't lose access to the visual content just because I can't see the image itself**.

> Related RFs/RNFs: RF-011, RF-012
> Related use cases: UC-05

---

**US-007**
As a **User**,
I want **the image's alt text to never be empty, missing, or a generic placeholder — even the first time an artwork is opened, or if generation fails**,
so that **I always get some meaningful text, generated on demand if needed**.

> Related RFs/RNFs: RF-012, RF-013
> Related use cases: UC-05

---

## Detailed Use Cases

### UC-05 — Consume Alt Text of the Artwork's Image

| Field                | Detail                                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **Primary Actor**    | User (Visitor) — relevant to every User, since the `alt` attribute is always applied, not only to screen-reader users |
| **Secondary Actors** | Art Archive System, Multimodal LLM, Assistive Technology                                                              |
| **Preconditions**    | The User accesses an artwork's detail page                                                                            |
| **Postconditions**   | The artwork's image always has a non-empty, non-placeholder `alt` attribute                                           |

**Main Flow**

1. The User accesses an artwork's detail page.
2. The system checks whether the artwork's Alt Text is already persisted.
3. If it exists, the system applies the stored Alt Text — beginning with the standard AI-disclosure sentence — to the image's `alt` attribute.
4. If it does not exist, the back-end triggers a dedicated AI call (independent from the Insight Card calls) to generate it from the image and Harvard metadata.
5. Once generated, non-empty Alt Text is persisted under the artwork's ID and applied to the `alt` attribute.
6. The assistive technology reads the `alt` attribute's content when the image receives focus.

**Alternative / Exception Flows**

- **4a.** The AI call fails, or the image is invalid or unavailable → the standard fallback message "Was not possible to generate an alt text for this image." is applied to the `alt` attribute; it is **not** persisted, and generation is retried on the artwork's next visit.
- **2a.** Harvard metadata is missing one or more fields → the Alt Text is generated using only the fields present; no field is guessed or inferred.

**Acceptance Criteria**

```gherkin
Feature: Alt Text applied to the artwork's image

  Scenario: Alt Text already persisted
    Given the artwork has Alt Text stored in the database
    When the front-end renders the artwork's image
    Then the img tag's alt attribute contains the AI-generated text, beginning with the standard disclosure sentence
    And the alt attribute is neither empty nor absent

  Scenario: Alt Text not yet generated
    Given the artwork does not yet have Alt Text stored
    When the front-end renders the artwork's image
    Then the back-end triggers a dedicated AI call to generate the Alt Text
    And, if generation fails, the fallback message "Was not possible to generate an alt text for this image." is applied instead
    And the alt attribute is neither empty nor absent in either case
```

> Related RFs/RNFs: RF-011, RF-012, RF-013
