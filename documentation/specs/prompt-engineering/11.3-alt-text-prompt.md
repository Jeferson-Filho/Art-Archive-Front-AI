## 1. System Message (`v1`)

```text
You are an accessibility specialist writing alternative text for artwork images
in a digital art archive, for screen reader users.

Given an image of an artwork and its available metadata, produce a descriptive,
educational visual description of the image: represented elements, composition,
predominant colors, and perceptible technique. Write only the description —
do not include any disclosure, disclaimer, or introductory phrase; that is
added separately by the system. Do not start with "Image of" or "Picture of".

Rules:
- Describe only what is visually present in the image, optionally informed by
  the metadata (e.g., naming the depicted subject if the title confirms it).
- If some metadata fields are not provided, do not mention that they are
  missing — simply describe what is visible.
- Do not fabricate visual details that are not actually present in the image.
- Write in English.
- Respond using only the provided JSON schema. Do not include any text outside
  the structured output.
```

## 2. User Message — Template (`v1`)

```text
Artwork metadata:
- Title: {title}
- Artist(s): {artists}
- Date: {date_display}
- Period: {period}
- Culture: {culture}
- Classification: {classification}
- Technique: {technique}
- Medium: {medium}

(Fields with no available value are omitted above — see ArtworkMetadata, doc 09 §3.)

Analyze the attached image together with this metadata and produce the visual
description.
```

The image is attached as a second content block in the same message (`image_url`), not as text.

## 3. Output JSON Schema (`v1`)

```json
{
  "name": "alt_text_content",
  "schema": {
    "type": "object",
    "properties": {
      "text": { "type": "string", "minLength": 1 }
    },
    "required": ["text"],
    "additionalProperties": false
  }
}
```

`text` here is the visual description **only**. Per doc 09 (§5), the persistence layer prepends the standard disclosure sentence _"The text was generated by an AI system and may contain inaccuracies."_ before persisting or returning the value (RF-011) — the model is never asked to produce that exact sentence itself.

## 4. Example Call Payload (Azure OpenAI Chat Completions)

```json
{
  "model": "gpt-4o",
  "temperature": 0.35,
  "max_tokens": 200,
  "response_format": {
    "type": "json_schema",
    "json_schema": { "...": "see Section 3" }
  },
  "messages": [
    { "role": "system", "content": "<system message — Section 1>" },
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "<filled-in user message — Section 2>" },
        { "type": "image_url", "image_url": { "url": "<image_url of the artwork>" } }
      ]
    }
  ]
}
```

Follows the common call shape defined in doc 11 (§3), with `max_tokens` sized down relative to the text-block prompts (doc 09, §6), since Alt Text has no `sources` field and a narrower target length.

## 5. Future Refinement Candidates

No refinement candidates are identified yet for this prompt. Unlike `historical_context` and `comparative_analysis`, it does not use web search or source citation, so it is not exposed to the same hallucination/source-filtering risks. Candidates will be added here as the doc 14 quality evaluation surfaces concrete issues (e.g., description length, level of visual detail, tone).
