# Block 1 — Insight Card: Text Generation via Multimodal LLM

The Insight Card is the narrative panel displayed on the detail page of each artwork. It is made up of two AI-generated text blocks — historical context and comparative analysis — displayed together within a single "Context information" section, as paragraphs rather than as separately titled subsections.

---

**RF-001 — Triggering Insight Card generation and existence check**

The system must check, when loading an artwork's detail page, whether the historical context block and the comparative analysis block already exist in the database for that artwork. This check is performed **independently for each block**: before any call to the AI API, the back-end must query the database to check whether each block has already been generated and persisted.

- If both blocks exist: the back-end returns both stored blocks and no call to the AI API is made.
- If only the historical context block is missing: the back-end triggers an AI API call to generate only the historical context block; the comparative analysis block is not regenerated.
- If only the comparative analysis block is missing: the back-end triggers an AI API call to generate only the comparative analysis block; the historical context block is not regenerated.
- If both blocks are missing: the back-end triggers **two separate AI API calls**, one per block, not a single combined call.

Regardless of which block(s) needed generation, the front-end displays a single loading state for the whole "Context information" section and only renders it once **both** blocks are available (retrieved from the database and/or returned by the AI API) — the two blocks are never shown one before the other. This check applies regardless of how many times the artwork has been accessed before.

**Scenario 001.1 — Neither block present in the database**

```gherkin
Given the user accesses an artwork's detail page
And neither the historical context block nor the comparative analysis block is stored in the database for this artwork
When the page finishes loading
Then the system displays the loading state for the "Context information" section
And the back-end triggers two separate AI API calls, one for the historical context block and one for the comparative analysis block
And the back-end waits for both responses for persistence
And the "Context information" section is only displayed once both blocks are ready
```

**Scenario 001.2 — Both blocks already present in the database**

> Related RFs/RNFs: RNF-002

```gherkin
Given the user accesses an artwork's detail page
And both the historical context block and the comparative analysis block are ALREADY stored in the database for this artwork
When the page finishes loading
Then the system displays the "Context information" section directly, returned from the database
And no request is made to the AI API
And the response time is lower than the time of a new generation
```

**Scenario 001.3 — Only the historical context block is missing**

```gherkin
Given the user accesses an artwork's detail page
And the comparative analysis block is ALREADY stored in the database for this artwork
And the historical context block is NOT stored in the database for this artwork
When the page finishes loading
Then the system displays the loading state for the "Context information" section
And the back-end triggers a single AI API call to generate only the historical context block
And no AI API call is made to generate the comparative analysis block
And the "Context information" section is only displayed once the historical context block is ready, showing both blocks together
```

**Scenario 001.4 — Only the comparative analysis block is missing**

```gherkin
Given the user accesses an artwork's detail page
And the historical context block is ALREADY stored in the database for this artwork
And the comparative analysis block is NOT stored in the database for this artwork
When the page finishes loading
Then the system displays the loading state for the "Context information" section
And the back-end triggers a single AI API call to generate only the comparative analysis block
And no AI API call is made to generate the historical context block
And the "Context information" section is only displayed once the comparative analysis block is ready, showing both blocks together
```

---

**RF-002 — Generation of the historical context block**

The LLM must generate, for each artwork, a narrative text block with historical context containing: historical period, artistic movement, relevant biography of the artist, and cultural influences of the artwork. The generation must use the artwork's image and the artwork's metadata provided by the Harvard Art Museums API as input: **title, artist, technique, culture, and period**.

**Scenario 002.1 — Successful generation**

```gherkin
Given the back-end receives a generation request for an artwork with a valid image and complete metadata (title, artist, technique, culture, period) from the Harvard Art Museums API
When the LLM processes the request
Then the back-end returns a non-empty historical context text block
And the text mentions at least the artwork's historical period and artistic movement
```

**Scenario 002.2 — Incomplete metadata**

```gherkin
Given the back-end receives a generation request for an artwork whose metadata from the Harvard Art Museums API is missing one or more of the fields (title, artist, technique, culture, period)
When the LLM processes the request with only the metadata fields that are present
Then the back-end returns a historical context block based only on the fields present
And the LLM MUST NOT create, infer, or guess information to fill in a missing field
And the portion of the text that would depend on a missing field is simply not generated
And it does not return an error due to the absence of fields
```

**Scenario 002.3 — Not enough context about the artwork**

```gherkin
Given the back-end receives a generation request for an artwork, regardless of whether its metadata is complete or not
And the LLM does not have enough reliable information/context about the artwork itself to generate the historical context block
When the back-end receives the LLM's response
Then the back-end returns an empty string ("") for the historical context block
And the LLM MUST NOT fabricate content to fill the gap
And, if the comparative analysis block was generated successfully, only that block's text is shown to the user
And the empty result is not persisted in the database
And a new generation attempt for the historical context block is made the next time the artwork is visited
```

---

**RF-003 — Generation of the comparative analysis block**

The LLM must generate, for each artwork, a text block with comparative analysis containing a reference to at least one other artist or artwork with similar characteristics in terms of period, technique, or culture.

**Scenario 003.1 — Successful generation**

```gherkin
Given the back-end receives a generation request for an artwork with valid image and metadata
When the LLM processes the request
Then the back-end returns a non-empty comparative analysis text block
And the text references at least one other artist or artwork with a similar period, technique, or culture
```

**Scenario 003.2 — Generation not successful**

```gherkin
Given the back-end receives a generation request for an artwork
And the LLM does not have enough reliable information to reference at least one other artist or artwork with a similar period, technique, or culture
When the back-end receives the LLM's response
Then the back-end returns an empty string ("") for the comparative analysis block
And the LLM MUST NOT fabricate a comparison to fill the gap
And, if the historical context block was generated successfully, only that block's text is shown to the user
And the empty result is not persisted in the database
And a new generation attempt for the comparative analysis block is made the next time the artwork is visited
```

---

**RF-004 — Persisting the generated content after the first generation**

> Related RFs/RNFs: RF-001, RF-002, RF-003

After generation, the back-end persists only the blocks that were successfully generated in the PostgreSQL database, under the artwork's ID, before returning the response to the front-end. A block that returned an empty string is **not** persisted — it remains missing in the database and is picked up again on the artwork's next visit.

**Scenario 004.1 — Successful persistence**

```gherkin
Given the LLM has returned a non-empty historical context and a non-empty comparative analysis for an artwork
When the back-end receives the LLM's response
Then the back-end persists both blocks in the database
And the record is created with the artwork's ID as the key
And the back-end returns the content to the front-end
```

**Scenario 004.2 — Persistence failure**

```gherkin
Given the LLM has returned non-empty content for an artwork
And the database returns an error when trying to save the record
When the back-end attempts to persist the content
Then the back-end returns the generated content to the front-end even without persistence
And logs the persistence error
And does not display an error message to the end user
```

**Scenario 004.3 — Only one block persisted**

```gherkin
Given the LLM has returned a non-empty text for one block and an empty string for the other
When the back-end receives the LLM's response
Then the back-end persists only the non-empty block in the database
And the empty block is not written to the database
And a new generation attempt for the empty block is made the next time the artwork is visited
```

---

**RF-005 — Displaying the Insight Card on the detail page**

The front-end must display the Insight Card on the artwork's detail page as a single section titled "Context information," presenting the historical context text followed by the comparative analysis text as paragraphs within that same section. The two blocks must not be displayed as separately titled subsections.

If one of the two blocks was returned as an empty string, the section must display only the other block's text, with no placeholder or error shown for the empty block. If both blocks were returned as an empty string, the section must display the standard message "Was not possible to generate an educational text for this artwork." instead of any block text.

**Scenario 005.1 — Display after generation**

```gherkin
Given the back-end has successfully returned the Insight Card content
When the front-end receives the response
Then the Insight Card is displayed on the detail page as a single "Context information" section
And the section contains the historical context text as one or more paragraphs
And the section contains the comparative analysis text as one or more paragraphs
And neither block is displayed under its own separate title
```

**Scenario 005.2 — Only one block was generated**

```gherkin
Given the back-end returns a non-empty text for one block (historical context or comparative analysis)
And the back-end returns an empty string ("") for the other block
When the front-end receives the response
Then the "Context information" section displays only the non-empty block's text, as one or more paragraphs
And no placeholder, blank paragraph, or error is shown for the empty block
```

**Scenario 005.3 — Both blocks failed to generate**

```gherkin
Given the back-end returns an empty string ("") for both the historical context and the comparative analysis blocks
When the front-end receives the response
Then the "Context information" section displays the message "Was not possible to generate an educational text for this artwork."
And no empty paragraphs are displayed in the section
```

---

**RF-006 — Insight Card loading state**

While the Insight Card content is being generated, the front-end must display a visible loading state in the space reserved for the card, indicating that the process is in progress.

**Scenario 006.1 — Loading visible**

```gherkin
Given the user accesses an artwork's detail page with no persisted Insight Card
When the generation is triggered
Then the front-end displays a loading indicator in the Insight Card area
And the rest of the page (title, image, basic metadata) remains visible and usable
```

---

**RF-007 — Insight Card error state**

> Related RFs/RNFs: RF-002, RF-003, RF-005, RF-010

Per-block generation failures follow the empty-text behavior defined for each block: a block that fails to generate for any reason (timeout, AI API error, insufficient data, malformed response) is returned as an empty string, and if the other block succeeded, the front-end displays only that block's text — no error message is shown for a single failed block. The Insight Card's error state is only triggered when **both** blocks fail to generate:

- If the two failures are not both timeouts (e.g., both are a different kind of error, or one is a timeout and the other is not), the front-end displays the standard message "Was not possible to generate an educational text for this artwork." in the Insight Card area.
- If both failures are specifically due to a timeout, the front-end displays a timeout-specific message instead (e.g., "The request took too long. Please try again later.").

The rest of the detail page (image, metadata, titles) must remain accessible and functional regardless of the Insight Card's state.

**Scenario 007.1 — Only one block fails to generate**

> Related RFs/RNFs: RF-005

```gherkin
Given the user accesses an artwork's detail page with no persisted Insight Card
And the generation of one block (historical context or comparative analysis) fails, for any reason
And the generation of the other block succeeds
When the front-end receives the response
Then no error message is displayed in the Insight Card area
And the "Context information" section displays only the successfully generated block's text
```

**Scenario 007.2 — Both blocks fail with non-timeout or mixed errors**

```gherkin
Given the user accesses an artwork's detail page with no persisted Insight Card
And the generation of both the historical context and comparative analysis blocks fails
And at least one of the two failures is not a timeout
When the front-end receives the response
Then the front-end displays the standard message "Was not possible to generate an educational text for this artwork." in the Insight Card area
And the rest of the page remains functional
```

**Scenario 007.3 — Both blocks fail due to timeout**

```gherkin
Given the user accesses an artwork's detail page with no persisted content
And the requests to the AI API for both the historical context and comparative analysis blocks exceed the configured time limit
When the timeout is reached for both blocks
Then the back-end returns a timeout error response to the front-end
And the front-end displays a timeout-specific error message in the Insight Card area (e.g. "The request took too long. Please try again later.")
And the artwork's title, image, and metadata remain visible and functional
```

---

**RF-008 — AI-generated content disclosure**

The front-end must display a persistent, clearly visible notice next to the Insight Card's "Context information" section, informing the user that the text was generated by an AI system and may contain inaccuracies. This notice must be shown whenever Insight Card content is rendered, regardless of whether it was just generated or retrieved from the database, and must use the standard message: **"This content was generated by artificial intelligence and may contain inaccuracies."**

**Scenario 008.1 — Disclosure shown on freshly generated content**

```gherkin
Given the back-end has successfully returned newly generated Insight Card content
When the front-end displays the "Context information" section
Then the front-end displays the standard notice "This content was generated by artificial intelligence and may contain inaccuracies."
```

**Scenario 008.2 — Disclosure shown on content served from the database**

```gherkin
Given the Insight Card content for an artwork is already persisted in the database
When the front-end displays the content retrieved from the database
Then the front-end displays the same standard notice "This content was generated by artificial intelligence and may contain inaccuracies."
```

**RF-009 — Open web search as an LLM capability**

> Related RFs/RNFs: RF-002, RF-003, RF-010

Once the artwork's image and its Harvard Art Museums API metadata (title, artist, technique, culture, and period) have already been sent as input to the LLM, the LLM must be able to search the web for additional information about the artwork, its artist, period, technique, or culture, to use while producing the historical context and comparative analysis blocks. This web search is open: no specific website or source is predefined, hardcoded, or required — the LLM decides what to search for and which pages to consult, subject only to the source-relevance rule.

**Scenario 009.1 — Web search triggered after input is sent**

```gherkin
Given the back-end has already sent the artwork's image and Harvard Art Museums API metadata to the LLM
When the LLM begins producing the historical context or comparative analysis block
Then the LLM is allowed to search the web for additional information about the artwork, its artist, period, technique, or culture
And the search is not restricted to a predefined list of websites or sources
```

**Scenario 009.2 — Search results feed the returned sources**

> Related RFs/RNFs: RF-010

```gherkin
Given the LLM has performed a web search while generating a text block
When the LLM produces the historical context and/or comparative analysis text
Then the web pages the LLM consulted are the candidate sources evaluated under the relevance rule
And only the sources considered appropriate are returned to the front-end
```

---

**RF-010 — Returning sources used for the generated text**

> Related RFs/RNFs: RF-005

For each generated text block, the back-end must return the sources/references the LLM used to produce the content. Each source must contain relevant information about the artwork — e.g. about the artist, period, technique, or culture, not necessarily the artwork itself. A source with none of this information is considered inappropriate and must be discarded. If no appropriate source remains for a block, the back-end returns an empty string ("") for that block.

**Scenario 010.1 — Successful generation with sources**

```gherkin
Given the back-end receives a generation request for an artwork with valid image and metadata
When the LLM successfully produces the historical context and/or comparative analysis text
Then the back-end returns, together with each text block, the sources used to generate it
And each returned source contains relevant information about the artwork, its artist, period, technique, or culture
And the front-end displays the sources alongside the corresponding text block
```

**Scenario 010.2 — No appropriate source available**

> Related RFs/RNFs: RF-007

```gherkin
Given the back-end receives a generation request for an artwork
And none of the sources available to the LLM contains relevant information about the artwork, its artist, period, technique, or culture
When the back-end receives the LLM's response
Then the back-end returns an empty string ("") for the affected block
And no sources are returned for that block
And this is not treated as a generation error
```
